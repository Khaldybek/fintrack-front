================================================================================
                        ОПИСАНИЕ ПРОЕКТА FINTRACK-FRONT
================================================================================

FinTrack — это веб-приложение для личного учёта финансов. Фронтенд написан на 
React (Next.js) и общается с бэкендом по REST API. Пользователь может вести 
транзакции по счетам, ставить лимиты по категориям (бюджеты), копить на цели, 
смотреть аналитику и прогноз кассового разрыва. Интерфейс на русском языке.


--------------------------------------------------------------------------------
ЧТО ЭТО ЗА ПРОЕКТ
--------------------------------------------------------------------------------

Это клиентская часть (фронтенд) системы FinTrack. Серверная часть работает 
отдельно (обычно на порту 3000), фронт — на порту 3001. Приложение рассчитано 
на одного пользователя: войти можно по email и паролю, после входа доступны 
все разделы в зависимости от плана (Free или Pro).

Главные идеи:
  • Один аккаунт — свои счета, категории, транзакции, бюджеты и цели.
  • Безопасность: access-токен хранится только в памяти, refresh-токен — 
    в httpOnly cookie на бэкенде; по нему при истечении сессии делается 
    обновление без повторного ввода пароля.
  • Удобство: общий shell (шапка и навигация), модальные окна для быстрых 
    действий, фильтры и подсказки там, где нужно.


--------------------------------------------------------------------------------
ТЕХНОЛОГИИ
--------------------------------------------------------------------------------

  • Next.js 16 (App Router) — маршрутизация, layout, серверные и клиентские 
    компоненты.
  • React 19 — интерфейс, хуки, контекст (в том числе AuthProvider).
  • TypeScript — типы для API, пропсов и состояния.
  • Tailwind CSS 4 — стили (утилитарные классы, переменные для темы).
  • Biome — линтер и форматирование кода.

Сборка и запуск:
  • npm run dev   — режим разработки (фронт на http://localhost:3001).
  • npm run build — продакшен-сборка.
  • npm run start — запуск собранного приложения.

Бэкенд задаётся переменной окружения NEXT_PUBLIC_API_URL (по умолчанию 
http://localhost:3000), префикс API — /v1.

Маршруты и навигация заданы в shared/config/routes.ts. В шапке приложения

Дополнительные экраны (кэшфлоу, подписки, семья, безопасность, кредиты, 
категории) доступны через блок «Дополнительные экраны» в профиле или по 
прямым ссылкам.


--------------------------------------------------------------------------------
ОСНОВНЫЕ РАЗДЕЛЫ
--------------------------------------------------------------------------------

  • Главная (Dashboard) — текущий баланс, доход/расход за месяц, финансовый 
    индекс, прогноз до конца месяца, инсайты.

  • Транзакции — список доходов и расходов по датам; фильтры по периоду, 
    категории и поиску; добавление операции (сумма → категория → счёт + 
    комментарий); редактирование, удаление, разбивка по категориям (splits); 
    шаблоны частых операций. Заглушки под голосовой ввод и OCR чека.

  • Аналитика — отчёты по месяцам, тренды, топ категорий, экспорт.

  • Бюджеты и цели — одна страница с вкладками:
    — Бюджеты: лимиты по категориям, прогресс (в норме / внимание / 
      перерасход), пороги 70%, 85%, 100%; создание, редактирование, удаление.
    — Цели: цели накопления с суммой и сроком, прогресс-бар, пополнения и 
      история операций по цели, аналитика по цели.

  • Профиль — данные аккаунта, блок «Счета» (список счетов и кнопка 
    «Добавить счёт»), безопасность, план (Free/Pro) и лимиты, ссылки на 
    доп. экраны.

  • Кэшфлоу — прогноз баланса до конца месяца, риск разрыва, минимум месяца.

  • Подписки, семейный режим, безопасность, уведомления, кредитный 
    калькулятор, категории — отдельные страницы с соответствующим функционалом.


--------------------------------------------------------------------------------
АВТОРИЗАЦИЯ И БЕЗОПАСНОСТЬ
--------------------------------------------------------------------------------

  • Вход: email + пароль; после успешного ответа бэкенд отдаёт access token 
    (в теле ответа) и выставляет refresh token в httpOnly cookie.

  • Access token хранится только в памяти (переменная в api/client.ts) и 
    передаётся в заголовке Authorization при каждом запросе.

  • Refresh token фронт не читает: он лежит в cookie. При 401 от любого 
    метода API клиент отправляет POST /v1/auth/refresh с credentials: "include", 
    браузер автоматически подставляет cookie; бэкенд по нему возвращает новую 
    пару (access в ответе, при необходимости обновляет cookie). После успешного 
    refresh исходный запрос повторяется.

  • Если refresh не удался (например, истёк срок), пользователя перенаправляют 
    на страницу входа.

  • При первой загрузке приложения вызывается refresh(), чтобы восстановить 
    сессию по cookie без повторного логина.


--------------------------------------------------------------------------------
API И ДАННЫЕ
--------------------------------------------------------------------------------

Все запросы идут на базовый URL из NEXT_PUBLIC_API_URL, префикс /v1. 
Используются методы GET, POST, PATCH, DELETE; тело — JSON, кроме эндпоинтов 
с загрузкой файлов (например, receipt-ocr — FormData).

Основные группы эндпоинтов:
  • /auth — login, register, refresh, logout
  • /me, /me/plan — профиль и план
  • /accounts — счета (CRUD)
  • /categories — категории (CRUD)
  • /transactions — транзакции (список, одна, создание, обновление, удаление, 
    splits, шаблоны, voice-parse, receipt-ocr)
  • /budgets — бюджеты (CRUD)
  • /goals — цели (CRUD, записи по цели, аналитика)
  • /dashboard — сводка, прогноз, индекс
  • /analytics — отчёты, тренды, экспорт
  • /credits — кредиты/долги
  • /subscriptions — подписки
  • и другие по мере появления разделов

Типы запросов и ответов описаны в shared/api/types.ts; клиент в shared/api/client.ts 
обрабатывает 401, refresh по cookie и редирект на логин при неудаче.


--------------------------------------------------------------------------------
ЧТО ВАЖНО ЗНАТЬ РАЗРАБОТЧИКУ
--------------------------------------------------------------------------------

  1. Добавление нового раздела: страница в app/(main)/..., при необходимости 
     пункт в ROUTES и в навигации (AppShell или ExtraScreensNav).

  2. Новый вызов к API: функция в shared/api/*.ts, при необходимости типы 
     в types.ts; использование через apiClient с учётом 401 и refresh по cookie.

  3. Бюджеты и цели объединены на одной странице /planning с вкладками; 
     старые маршруты /budgets и /goals делают редирект на /planning.

  4. Счета нужны для создания транзакций; они добавляются в профиле в блоке 
     «Счета». Без ни одного счёта кнопка «Сохранить» в форме добавления 
     транзакции неактивна, с подсказкой перейти в профиль.

  5. Стили — Tailwind и CSS-переменные в globals.css (--ink-*, --line, 
     --surface-*, и т.д.); общие классы вроде .card, .action-btn, .auth-field 
     заданы там же.

  6. Линтинг и формат: npm run lint, npm run format (Biome).


--------------------------------------------------------------------------------
КОРОТКО
--------------------------------------------------------------------------------

FinTrack-front — это клиент личного финансового приложения: дашборд, 
транзакции по счетам с категориями и шаблонами, бюджеты и цели на одной 
странице, аналитика, прогноз, профиль со счетами и подпиской. Стек — Next.js, 
React, TypeScript, Tailwind. Авторизация через access token в памяти и 
refresh token в httpOnly cookie; при 401 сессия обновляется по cookie, 
при неудаче — редирект на логин. Описание актуально на момент написания 
и может дополняться по мере развития проекта.
