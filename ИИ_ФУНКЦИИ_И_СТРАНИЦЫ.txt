
ТРАНЗАКЦИИ (/transactions)
--------------------------
• Умный ввод из текста/голоса (AI)
  Где: модалка «Добавить транзакцию» (блок «Умный ввод»).
  Цель: пользователь вводит фразу («1500 на такси вчера») — подставляются сумма, дата, категория, счёт, комментарий.
  API: POST /v1/transactions/voice-parse.

• Подсказка категории по memo (AI)
  Где: модалка «Добавить транзакцию» (шаг 3) и модалка «Редактировать транзакцию».
  Цель: по тексту операции (например из банка) — подсказка категории и нормализованное имя мерчанта.
  API: POST /v1/transactions/suggest-category.

• Чек по фото (AI)
  Где: модалка «Добавить транзакцию» (блок «Чек по фото»); кнопка «Сканировать чек по фото» в сайдбаре страницы транзакций.
  Цель: загрузка фото чека — подставляются сумма, дата, магазин, категория.
  API: POST /v1/transactions/receipt-ocr (multipart).


ДАШБОРД (/)
-----------
• Инсайт дня (AI)
  Где: карточка «Финансовая погода», блок «Персонализированный инсайт дня».
  Цель: один персонализированный совет на основе баланса и прогноза (кеш ~6 ч).
  API: GET /v1/dashboard/insight.

• Финансовый индекс 0–100
  Где: карточка «Финансовый индекс» с факторами.
  Цель: оценка состояния финансов и факторы (положительные/отрицательные).
  API: GET /v1/dashboard/index.

• Прогноз с AI-объяснением
  Где: карточки «Текущий баланс», «Прогноз до конца месяца», сайдбар «Прогноз».
  Цель: прогноз баланса до конца месяца; explanation — всегда, explanationAi — краткое объяснение от ИИ (если включено).
  API: GET /v1/dashboard/forecast.


ПРОГНОЗ КАССОВОГО РАЗРЫВА (/cashflow)
--------------------------------------
• Те же данные, что на дашборде: прогноз, алерты, инсайт дня, explanationAi в блоке «Рекомендация».
  Цель: сводка по ликвидности и рекомендации.


АНАЛИТИКА (/analytics)
----------------------
• AI-резюме месячного отчёта
  Где: блок «Финансовый отчёт месяца» — подблок «AI-резюме».
  Цель: короткий абзац (доход, расход, топ категорий, накопления) и короткая строка для шаринга.
  API: GET /v1/analytics/monthly-report/summary (query: year, month).

• Аномалии расходов
  Где: сайдбар «Аномалии расходов».
  Цель: выделение аномальных месяцев по расходам (возможная ИИ-логика на бэке).
  API: GET /v1/analytics/anomalies.

• Heatmap расходов
  Где: сайдбар «Heatmap расходов» + поле explanation.
  Цель: визуализация активности по дням за 90 дней; explanation может быть от ИИ.
  API: GET /v1/analytics/heatmap.


СВОДКА ПО API
-------------
Транзакции:  voice-parse, suggest-category, receipt-ocr.
Дашборд:     summary, forecast, insight, index, alerts, salary-schedules.
Аналитика:   monthly-report/summary, anomalies, heatmap (и др. без ИИ).
