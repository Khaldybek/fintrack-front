# Forgot password и Reset password — разница для фронта

## Кратко

| Что | Когда | Кто вызывает | Куда ведёт |
|-----|--------|--------------|------------|
| **forgotPassword** | Пользователь **не помнит** пароль и просит прислать ссылку на почту | Фронт (страница «Забыли пароль?») | Бэкенд отправляет письмо со ссылкой |
| **resetPassword** | Пользователь **перешёл по ссылке из письма** и вводит новый пароль | Фронт (страница «Новый пароль» с токеном в URL) | Пароль на бэкенде меняется |

---

## Шаг 1 — Forgot password (запрос ссылки)

**Цель:** пользователь забыл пароль → мы отправляем ему на email одноразовую ссылку для сброса.

- **Страница:** `/forgot-password`  
- **API:** `POST /v1/auth/forgot-password`  
- **Тело:** `{ "email": "user@example.com" }`  
- **JWT не нужен** (пользователь ещё не входит в аккаунт).

**Что делает фронт:**
1. Показывает форму: одно поле — email.
2. По кнопке «Отправить ссылку» вызывает `forgotPassword(email)`.
3. После ответа 200 показывает нейтральное сообщение вроде: «Если этот email зарегистрирован, вы получите письмо со ссылкой для сброса пароля».

**Что делает бэкенд:**  
Если пользователь с таким email есть и у него есть пароль (не только вход через Google), создаётся ссылка вида `{FRONTEND_URL}/reset-password?token=...`, старые ссылки отзываются, письмо уходит на email. Ссылка живёт, например, 1 час.

**Откуда пользователь попадает на этот шаг:**  
Со страницы входа («Забыли пароль?») или из профиля («Сброс пароля (Reset password)»).

---

## Шаг 2 — Reset password (установка нового пароля)

**Цель:** пользователь перешёл по ссылке из письма → вводит новый пароль, мы его сохраняем.

- **Страница:** `/reset-password?token=...` (токен в query из письма).  
- **API:** `POST /v1/auth/reset-password`  
- **Тело:** `{ "token": "...", "newPassword": "newSecurePass123" }`  
- **JWT не нужен** (достаточно токена из ссылки).

**Что делает фронт:**
1. Читает `token` из URL (`?token=...`).
2. Показывает форму: новый пароль + повтор пароля (например, не менее 8 символов).
3. По кнопке «Сохранить пароль» вызывает `resetPassword(token, newPassword)`.
4. После 200 — сообщение об успехе и редирект на `/login`.

Если в URL нет `token` — показываем сообщение «Ссылка недействительна» и ссылку на `/forgot-password`.

**Что делает бэкенд:**  
Проверяет токен, при успехе меняет пароль пользователя и инвалидирует токен.

**Откуда пользователь попадает на этот шаг:**  
Только по ссылке из письма, которое пришло после шага 1 (forgot password).

---

## Сводка по API на фронте

```ts
// Шаг 1 — пользователь ввёл email на /forgot-password
forgotPassword(email: string)  // POST /v1/auth/forgot-password, body: { email }

// Шаг 2 — пользователь на /reset-password?token=..., ввёл новый пароль
resetPassword(token: string, newPassword: string)  // POST /v1/auth/reset-password, body: { token, newPassword }
```

**Итого:**  
**forgotPassword** — «пришлите мне ссылку на сброс» (один запрос по email).  
**resetPassword** — «вот токен из ссылки и новый пароль, сохраните» (один запрос с токеном и паролем).
